## P0 · 数据与状态修复

都是读代码确认过的根因,不需要设计决策的直接修,需要拍板的单独列在 §8。

### P0-1 花费「剩余」两个口径(¥11,822 vs ¥10,919)

- **根因**:Dashboard 花费卡(`dashboard/dashboard.ts:334-375`)在当前国家有预算时,用的是「这个国家的预算 − 这个国家的花费」。行程结束后 `currentLeg()`(`data/trip-phase.ts:59-66`)回落到**最后一站**,所以 10 月 12 日还在算丹麦:26,500 − 14,678 = ¥11,822(55%)。Expenses 页(`expenses/expenses.ts:149-172`)用的是全程预算:85,000 − 74,081 = ¥10,919(87%)。两边的数字都没算错,但口径不同,而且只靠一个很小的 "Denmark ·" 区分。
- **改法**:
  - 「剩余 / 进度条」**永远是全程口径**:全程预算 − 总花费,和 Expenses 页一致。
  - 国家预算只在 `phase === 'during'` 时作为**第二行**显示,带明确标签,例如「丹麦 · 已花 ¥14,678 / ¥26,500」。
  - 行程结束后不再显示任何国家口径。
- 顺手修:`dashboard.ts:362-373` 的 "left / over / % of" 是硬编码英文,改成走 `t()`;国家名用本地化名称,不直接用 `leg.country`。
- 进度条颜色:两个页面的阈值本来一致(≥100% 珊瑚红 / ≥80% 琥珀 / 其他绿),这次一起换成 token(见 P1b)。口径统一后,两边颜色自然一致。

### P0-2 侧栏「Current Trip · 109 days ago」

- **根因**:`core/sidebar.ts:183-216` 用的是真实时钟 `new Date()`,不是 `appNow()`,所以时间回溯对它不生效;而且它完全不看 `endDate`。
- **改法**:改用 `tripPhase()` 和 `appNow()`:
  - 出发前:「还有 N 天出发」
  - 旅途中:「第 N 天 / 共 M 天」
  - 结束后:「旅程已结束 · 查看收官 ›」,点击进入 P6 的收官页
- 折叠侧栏的数字徽标:旅途中显示第几天,结束后显示 ✓ 或印章总数,不再显示 109。

## P1 · 视觉语言统一(最优先)

拆成三个分支,按 P1a → P1b → P1c 的顺序合入。每个分支都做完一类问题再合,不混在一起改。

### P1a 图标统一成 emoji + 中央注册表

**现状**
- 导航:7 个 PNG 插画(`core/app.ts:9-15,28-43` 的 `NAV_ITEMS`),外加 Dashboard 🏠 和 Agenda 🗓️ 两个 emoji。
- 页面标题:复用同一批 PNG(`sidebar.ts:126-149`)。
- emoji 映射表散落在至少 10 个文件里,`TRANSPORT_ICON(S)` 就定义了 4 次,而且同一个概念用了不同的 emoji(住宿有 🏠 和 🏨,火车有 🚆 🚄 🚂)。
- i18n 文案里也带 emoji,例如 `'🏨 Stays'`(`en.ts:381`)。

**方案**
1. 新建 `src/core/icons.ts`,作为全站唯一的图标注册表:
   ```ts
   // 现在只填 emoji;以后换插画时给每项加 img,渲染函数自动优先用图片
   export const ICONS = {
     nav: { dashboard: '🏠', agenda: '🗓️', prepare: '📋', compare: '⚖️', itinerary: '🧭',
            guide: '📖', map: '🌍', expenses: '🧾', journal: '📔', pack: '🎒', profile: '👤' },
     transport: { flight: '✈️', train: '🚆', bus: '🚌', ferry: '⛴️', car: '🚗' },
     stay: '🏨', /* … */
   } as const
   export function icon(key: IconKey, opts?): string  // 返回 <span class="ic"> 或 <img>
   ```
   具体用哪个 emoji 先按上表,你看过后再定。原则是**一个概念只对应一个 emoji**,导航里 Itinerary 和 Map 不能都用 🗺️。
2. 把所有散落的映射表都改成从注册表读:4 份 `TRANSPORT_ICON`、`plan-category-icon.ts`、`expense-helpers.ts` 和 `expense-defaults.ts` 两份消费分类(**顺便合成一份**)、天气、Where to go、Guide、Compare、Checklist、Journal。
3. i18n 文案里去掉 emoji,图标由渲染层通过 `icon()` 加。
4. `.ic` 统一尺寸和对齐:导航 20px、卡片标题 16px、行内 1em,并统一 `vertical-align` 和行高补偿,避免各个页面里 emoji 忽大忽小、上下错位。
5. 下线 PNG:`sidebar.ts` 的 `img.nav-icon-image` 分支保留(以后换插画要用),但不再有 PNG 数据走这条路。`icon/Nomad.png`、`Pack.png`、`Safety.png` 已经没有引用,可以直接删。

**说明**:emoji 在不同系统上长得不一样(Windows 的 Segoe 是扁平风格)。有了注册表以后,想统一画风只需要改一个文件:可以自托管 Twemoji / Fluent Emoji 的 SVG 子集,也可以换回插画。这次先不做。

### P1c 字体 / 符号 / 框线

**字体**
- 现状:`--font-ui`(Sora)被用了 334 次,`--font-body`(DM Sans)只有 2 次,实际上是一款字体包办一切。`--font-display` 在 `feed.css:83,470` 被引用但**从来没有定义**。`font-weight` 全是字面量,其中 700 有 297 次。
- 方案:
  - `--font-display`:Sora,只用于页面标题和大数字。
  - `--font-body`:DM Sans,正文、表单、列表都用它,把 Sora 退回到标题。这一条对去掉「卡通感」影响最大。
  - `--font-data`(新增等宽字体,建议 JetBrains Mono 子集,沿用 `scripts/build-fonts.mjs` 自托管):航班号、时刻、金额、重量、票据编号。
  - `--font-hand`(Caveat):只用在日记里。
  - 字重 token 只保留 3 档:`--fw-regular 400`、`--fw-medium 500`、`--fw-strong 600`。700 和 800 只给大数字。整体降一档字重,是从「卡通」走向「质感」的关键动作之一。
  - 341 处 font-size 字面量映射到 `--fs-*`,补一个 `--fs-2xs: 10px`。

**符号**:统一成一张表,写进注册表 `ICONS.glyph`。

| 含义 | 统一为 | 要替换的 |
|---|---|---|
| 关闭 | `✕` | `×`、`&times;` |
| 编辑 | `✎` | `✏️` |
| 删除 | `✕`(行内)/ 文字按钮 | `🗑` |
| 展开到抽屉 | `⤢` | 用作「打开」的 `›` |
| 外链 | `↗` | |
| 下拉 | CSS 画的 chevron | `▾`、`⌄` |
| 翻页 | `‹ ›` | `▶ ◀` |
| 添加 | `+`(半角) | 全角 `＋`(21 处) |
| 完成 | `✓` | `✔`、`✅`、`☑️`(作为 UI 符号时) |

**框线 / 圆角 / 阴影**
- 圆角:31 种值收敛到 5 个 token,按角色分配:
  - chip / 按钮:`--r-full`
  - 输入框:`--r-md`
  - 卡片内的小块:`--r-lg`
  - 卡片:`--r-xl`,从 24px 降到 18px
  - 票据 / 小票这类纸质物件:`--r-sm`
  - `--r-2xl`(32px)取消。大圆角是卡通感的主要来源之一。
- 边框:
  - 只保留两种:`1px` 细线和 `1.5px` 强调线。
  - 虚线**只**用于「添加 / 占位」和票据撕口。
  - 2px 以上只给焦点环。
- 阴影:76 处字面量收敛到 `--shadow-sm/md/lg`。
  - 普通卡片改成细线 + 极弱阴影。
  - 明显的阴影只留给「浮起来」的东西:抽屉、弹窗,以及 P3 里的纸质物件。

**防回退**:新增 `src/core/design-lint.test.ts`(和现有的 `dashboard-keys.test.ts` 同一种思路),扫描 CSS 和 TS,断言以下情况的数量不超过白名单基线:颜色字面量、圆角字面量、`font-weight` 字面量、注册表以外的 emoji。每清理一批就把基线下调一次。

**P1 验收**:Dashboard / Itinerary / Expenses / Journal 四个页面在亮暗两套下各截一张图,和改之前并排对比;对比度测试和 design-lint 测试通过。

## P2 · 行李秤

**数据(不改)**:每个包有 `label`、`kind`(suitcase / backpack / personal)、`selfWeightG`、`limitG`(0 表示不限)和物品列表(`data/schema/pack.ts:24-52`)。总重 = 物品重 + 空包重,超重判断 = `limitG > 0 && weight > limitG`(`pack-helpers.ts:110-126`)。

**新增内容只有展示层**
- 纯函数 `data/weigh-in.ts`:`weighIn(containers, items) → [{id, label, kind, weightG, limitG, verdict: 'pass'|'over'|'nolimit', diffG}]`,配单元测试。它复用 `pack-helpers` 里现有的计算,**不另写一份重量公式**。
- 组件 `views/prepare/weigh-scale.ts` + `weigh-scale.css`:纯 DOM,用 CSS 动画 / Web Animations API,不引入库。

**交互**
1. **入口**:Pack 页包裹区顶部一个「⚖️ 称重」按钮;修改某个包的重量或限额后(停顿 600ms),**只给这一个包**自动播一次。Dashboard 的行李抽屉里也放一个「称重」按钮。
2. **场景**:机场值机柜台式的平台秤,带数字读数屏。读数用 `--font-data`,七段数码管风格。
3. **动画顺序**:按包的顺序,每个包(emoji,来自注册表,以后可以换成插画)从上方落到秤盘上 → 秤盘下沉回弹 → 读数从 0 滚动到实际重量,大约 700ms → 停稳后出结论。
   - **合格**:读数屏变绿,包上挂一张「✓ OK」行李牌,轻微回弹;秤的旁边显示「余 3.2 kg」。
   - **超重**:读数屏红色闪两下,秤盘轻微抖动(只水平晃两下,不夸张),包上挂航司那种橙色的「HEAVY」牌,显示「超出 1.3 kg」。
   - **不限重**:只显示读数,牌子上写「未设限额」。
   - 全部称完,底部一行汇总:「3 件 · 2 件合格 · 1 件超重」。
4. **减少动态效果**:跳过动画,直接显示最终读数和行李牌。
5. 单位跟随 `pk-weight-unit`(kg / g / lb / 斤)。

**前置**:P0-3 的输入框单位错误必须先修,否则称出来的数字本身就是错的。

**待你确认**:Dashboard 上「26.9 kg」包含了未分配的物品,但 schema 的注释说未分配物品「不计重」(`pack.ts:8`)。称重只针对包,所以未分配物品不会上秤;Dashboard 上的总数要不要排除它们,见 §8-Q6。

## P3 · 质感化 + 统一的拟物组件

### 3.1 现在为什么显得卡通

有五个原因叠在一起:

1. 高饱和的亮黄
2. 大圆角(24 / 32px)
3. 粗字重(700 到处都是)
4. 1.5–2px 的粗描边
5. 系统 emoji 当装饰

P1 处理掉了大部分,P3 在此基础上加「材质」。

### 3.2 材质规则(全站统一)

1. **只有一种材质:纸**。暖白纸底,物件用略亮的纸色;可以加一层极淡的纸纹(SVG `feTurbulence` 噪点做成 data URI,透明度 ≤ 3%,深色模式下关闭或减半)。
2. **只有一个光源**,在上方:阴影统一向下,浮起的物件才有阴影。
3. **允许的拟物细节只有 6 种**:撕口虚线、半圆缺口、条形码、印章墨迹、行李牌孔眼、小票锯齿边。不用描边卡通线,不用高光渐变。
4. **数字用等宽字体**,文字用 DM Sans,标题用 Sora。
5. **动效模拟物理**:物件落下、盖章、撕下,用 `--ease-out`;只有印章允许一点回弹。

## P4 · 护照印章

### 4.1 规则

- **一站一枚印章**:每个 leg 对应一枚,同一座城市去两次(例如哥本哈根)就有两枚,日期不同。
- **国家入境章**:第一次进入某个国家时,多一枚国家章。
- **什么时候算「获得」**:到达日 ≤ `appNow()`。所以时间回溯可以重放盖章过程,演示和自测都方便。
- **不新增数据**:印章完全从 route legs 推导出来;唯一需要存的是「这枚章的动画有没有播过」(第一版存 localStorage,键 `otr:stampSeen:<legId>`;要跨设备再挪到 `userPrefs`)。

### 4.2 印章生成(确定性,不需要美术资源)

- 纯函数 `data/stamps.ts`:`stampsFor(legs, today) → Stamp[]`,配单元测试。
- 形状由 `hash(城市名)` 从 6 种里选一种:圆、双圈、圆角矩形、六边形、椭圆、八角形。旋转角度在 ±12° 内,也由哈希决定。
- 颜色:每个国家一个**哑光墨色**,从国旗主色降饱和得到,登记在 `data/country-ink.ts`。
- 内容:城市名(英文大写)、国家 ISO3、到达日期、晚数,以及到达方式的小图标(✈️ / 🚆,来自注册表)。
- 墨迹质感:SVG `feTurbulence` + `feDisplacementMap` 做出不均匀的墨迹和缺损;深色模式下墨色提亮。
- 用 `--font-data` 渲染,带 `role="img"` 和 `aria-label`。

### 4.3 出现的位置

| 位置 | 改动 |
|---|---|
| Itinerary 列表 | 去掉「VISITED」灰色胶囊,在照片右下角盖上这一站的印章 |
| Itinerary 详情页 hero | 「VISITED」标签换成印章 |
| Dashboard 横幅 | 到达新城市后第一次打开时,横幅上播一次盖章动画(下落、压下、墨迹晕开,约 500ms),然后在城市名旁边留一枚小章。**布局不变** |
| 地图世界视图侧栏 | 护照册(P5) |
| 收官页 | 护照章节(P6) |

### 4.4 护照册

做成一个**抽屉**(复用 `core/drawer.ts`),不新增导航项。入口有三处:侧栏行程卡、地图侧栏、收官页。

- 每页 4 枚印章,按时间排列,纸张背景 + 页码;可以翻页,也可以按国家筛选。
- 点击印章 → 跳到行程里的这一站,或在地图上定位到这座城市。

## P5 · 地图:可旋转世界

### 5.1 先澄清 Marginalia 地图主界面的实际做法

读代码确认:Marginalia 地图主界面**不是正射投影的球体**。它是 amCharts5 的 `geoNaturalEarth1` 投影(一个椭圆形的世界),加上 `panX: 'rotateX'`:左右拖动时经度会旋转,世界像地球仪一样转过来、首尾相接;上下拖动只是平移(`Marginalia/src/map/map.ts:1012-1021`)。点击某个国家后切换成 Mercator 并放大,返回时再切回来(`:1024-1037`、`:1248-1265`、`:1318-1330`)。three.js 只用在角落那个装饰小地球和进场动画里,和这次无关。

**好消息**:On the Road 用的就是 amCharts5(从 CDN 加载),这一套可以几乎原样移植。如果你说的「立体」其实是想要一个真正的圆球,那就用 `geoOrthographic`,成本同样不高。见 §8-Q1。

### 5.2 地图页的新结构:两层

**① 世界层(新增,默认入口)**:你所有行程的足迹。

- 投影:`geoNaturalEarth1` + 左右拖动旋转,和 Marginalia 一样。滚轮和双指缩放;打开时从当前行程所在的经度开始。
- 国家着色:**按到访次数**混合哑光琥珀色(移植 Marginalia 的 `mixHexColor` / `heatColorForCount`,`map.ts:332,368`);没去过的国家是纸色。可以切换成「按行程着色」,每个行程一个颜色(复用 `trip-chooser.ts` 里的行程色)。
- 路线:每个行程画成一条细线,用 `MapLineSeries` 沿地球曲线绘制;悬停时高亮这一条,其他变淡。
- 右侧面板(仿照 Marginalia 的统计侧栏,换成旅行内容):
  - 足迹统计:国家数、城市数、晚数、总里程(按 leg 坐标算大圆距离)。
  - 护照册入口,以及最近 6 枚印章。
  - 行程列表,点击进入第二层。
- 点击国家 → 右侧面板显示这个国家的:去过的站点和印章、在这里的花费、日记数量和缩略图;同时切换到 Mercator 并放大到这个国家(Marginalia 的做法),省份下钻继续用现有的 `drillCountry`(`views/map/map.ts:1129`)。

**② 行程层(现有地图,基本保留)**:路线回放、编号站点、小人 hero、省份下钻、时间轴都保留。从世界层选择行程进入;如果有正在进行的行程,打开地图时直接进这一层,左上角有「← 世界」按钮。

### 5.3 技术要点

- 移植代码时使用 CDN 全局变量 `window.am5`,**不引入 npm 包**(两个仓库的加载方式不同)。
- `naturalEarth1` 仍然是平面投影,所以现有的 DOM 覆盖层(hero、飞机、标签,通过 `chart.convert()` 定位)不需要额外处理背面遮挡。如果改用 `geoOrthographic`,覆盖层要判断点是否在背面,背面的就隐藏。
- **主题切换**:现在地图颜色只在建图时读一次(`map-shared.ts:49`),切换主题后不会更新。这次加上 `theme` 变化的监听,重新给多边形和线上色,不重建整张图。
- Marginalia 里读书相关的视觉都不带过来:深色专用背景 `#302e2a`、`#6a5443` 边框、金色 hover、14 色复古调色板、拍立得卡片、打字机效果、五个 tab 的面板。全部用 On the Road 的 token 重做。
- 减少动态效果:不做自动旋转,点击国家时直接跳过去,不播缩放动画。

### 5.4 Dashboard 地图

保持现状(Mercator 缩略图 + Leaflet「这一天」)。只做一处:行程结束后,「整个旅程」模式下点击地图,进入地图页的世界层。
