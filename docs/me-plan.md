# P9 · 「我」：账户级入口的归位

> 2026-10-13 · 只覆盖网页版。**本文只是规划，没有改任何代码。**
> **已确认并实施（2026-10-13）**：P9.0 与 P9.1 已在分支 `feat/p8-polish` 完成（tsc / vitest / build / lint 通过）。owner 的决定：
> - Q1 放在侧栏**底部**，**UI 上要与其他功能页面区分**（实现：置底 + 分隔线 + 独立分组标题，不用琥珀底色，避免和当前页高亮打架）。
> - Q2 分组中文暂叫「**我的世界**」，英文 "My world"（非最终）：想体现这里装的不只是个人资料，而是**去过的地方、走过的路**。三项分别叫「我的护照」「我的足迹」「设置」。
> - Q3 入口改名；Q4 Profile 里的护照卡移除；Q5 旅行偏好问卷先不做；Q6 Dashboard 不再放地球仪/护照卡片。
>
> 与文中有出入之处以代码为准：
> - 「账户与设置」缩成「**设置**」（220px 侧栏放不下全称，且分组标题已经说明是「我」的东西）；`#profile` 页标题同改。
> - 侧栏 Map 的图标改为折叠地图 🗺️，🌍 留给「我的足迹」（两者原来撞图标）。
> - 手机没有侧栏：设置页顶部在 ≤768px 多出「我的世界」两行入口（护照、足迹），宽屏隐藏。
> - 「我」段不另做表单：它读写与护照资料页同一份数据（`passport/me`），编辑按钮直接打开护照自己的编辑器；默认昵称只有一份实现（`profile-me.ts` 的 `defaultNickname`，护照也用它）。
> - 旅行风格（`travelStyle`）是**行程**的字段，不是账户身份，所以没有放进「我」段。
> - 分享链接（`setAllowedViews`）不能授予「我的世界」页：那是接收者自己的账户，不是分享者的。

> 起因：owner 指出护照和地球仪挤在头像旁边的两个小图标里不合理（截图 5），应该有一个专门的入口，把用户资料、旅行偏好和这两样全局性的东西收在一起。

---

## 0. 一页结论

1. **问题不是图标太小，是这些东西没有家。** 护照和地球仪是**账户级**的（跨所有行程、属于「我」），但侧栏的结构只有「出发前 / 旅途中 / 回顾」三组，全是**行程级**的。没有地方放，就只能塞到头像旁边。
2. **解法：侧栏底部新增一个「我」区域**，和顶部的行程卡呼应：上面是「这趟旅行」，下面是「我这个人」。
3. **「我」不是一个新页面，是一个分组**，里面三件事：**我的护照**、**我的足迹（地球）**、**账户与偏好**（现有的 `#profile`）。
4. **头像回到纯粹的身份展示**：点头像进「账户与偏好」，不再挂两个图标。待盖章的红点移到「我的护照」那一项上。
5. **`#profile` 顺带整理**：现在它是「账户 / 护照卡 / 紧急信息 / 偏好」四段混排。改为三段：**我**（昵称、照片、国籍、旅行风格）、**旅行偏好**（语言、主题、时区、货币）、**账户与安全**（订阅、紧急联系人、退出）。

## 1. 现在为什么别扭

| 现象 | 原因 |
|---|---|
| 头像旁两个小图标（🛂 🌍），互相挤，不知道是什么 | 它们是账户级功能，但被放进了「身份展示」区 |
| 侧栏收起时这两个图标直接 `display: none` | 没地方放，收起态下这两个功能**完全消失** |
| Dashboard 曾经有护照口袋卡，后来被移除 | 入口到处试放，说明它本来就缺一个固定的家 |
| 地球仪的入口有 4 个（侧栏、Dashboard、Profile、路线图角落），但没有一个是「主」入口 | 同上 |
| `#profile` 里混着「护照卡」这种内容入口 | Profile 当了临时收纳箱 |

**一句话：** 行程级的东西有分组，账户级的东西没有。

## 2. 目标结构

```
侧栏
┌─────────────────────────┐
│ 👤 Holiday              │  ← 头像 + 名字，点击进「账户与偏好」
│    Account & billing    │     （不再挂图标）
├─────────────────────────┤
│ ✈ Europe 2026           │  ← 行程卡（现有，P8 已居中）
│   Day 16 of 74          │
├─────────────────────────┤
│ 🏠 Dashboard            │
│ 🗓 Agenda               │
│                         │
│ 出发前                   │
│ 📋 Prepare  ⚖ Compare   │
│ 旅途中                   │
│ 🧭 Itinerary 📖 Guide    │
│ 🗺 Map                  │  ← 这一趟的路线
│ 回顾                     │
│ 🧾 Expenses 📓 Journal   │
├─────────────────────────┤
│ 我                       │  ← 新分组（底部，与上面的行程内容分开）
│ 🛂 My passport      ●   │  ← 红点 = 有待盖章
│ 🌍 My atlas             │
│ ⚙ Account & settings    │
└─────────────────────────┘
```

**为什么放底部**：上面是「这趟旅行要做的事」，按时间推进；底部是「我的东西」，不随行程变化。这条分隔本身就在解释两者的区别。

## 3. 三个入口的分工

| 入口 | 是什么 | 路由 |
|---|---|---|
| 🛂 **我的护照** | 盖过的章，一人一本，跨所有行程 | `#passport` |
| 🌍 **我的足迹** | 走过的地方，立体地球仪 | `#atlas` |
| ⚙ **账户与设置** | 我是谁 + 偏好 + 账户 | `#profile` |

三者互通（已有）：护照桌角有地球仪、地球仪桌角有护照、国家卡片两边跳。

## 5. `#profile` 重新分段

现在：账户 → 护照卡 → 紧急信息 → 偏好（四段，顺序偶然）。

改为**三段，按「从我到系统」排**：

| 段 | 内容 | 来源 |
|---|---|---|
| **我** | 头像、昵称、国籍、旅行风格（独行 / 情侣 / 家庭 / 朋友 / 团队）、家乡城市 | 新：昵称/照片/国籍与护照资料页**共用同一份数据**（P7 已有 `passport/me`）；旅行风格来自 `TRAVEL_STYLES`（schema 已有，目前只在建行程时用） |
| **旅行偏好** | 语言、主题、首页时区、默认货币、减少动态效果 | 现有 prefs-mount + home-tz |
| **账户与安全** | 订阅/配额、紧急联系人与证件、退出登录 | 现有 account + emergency |

- 护照卡从 Profile **移除**（它现在在侧栏有自己的入口，不必在这里再放一个）。
- 「我」段里的昵称/照片/国籍改动会同步到护照资料页，反之亦然 —— 一处编辑，两处生效。

## 6. 旅行偏好：要不要现在就做？

owner 提到「填写用户的基本信息、旅行偏好」。我的建议是**分两步**：

- **P9.1（建议现在做）**：只做**结构** —— 侧栏「我」分组 + Profile 三段重排 + 昵称/国籍与护照共用。不新增任何需要用户填的字段。
- **P9.2（之后再看）**：真正的「旅行偏好」问卷（预算档位、节奏快慢、住宿偏好、饮食禁忌…）。这些只有在**有人消费它们**时才有价值（比如 AI 生成攻略、行程建议时读取）。现在没有消费方，填了也是死数据。

**所以 P9.1 不会凭空造字段**，只把已经存在的东西（昵称、照片、国籍、旅行风格）归位。
